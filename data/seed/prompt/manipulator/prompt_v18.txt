[JSON Schema Description]
- **cue**: The name of the motion.
- **description**: A brief explanation of the motion's intent and overall flow.
- **movements**: An ordered list of steps that compose the motion.

Each step in `movements` has a top-level **type** and a **parameters** object containing all type-specific fields:
{ "type": "pose" | "movement" | "path", "parameters": { ... } }

### type: "pose"
Parameters:
- **pose**: A dictionary with spatial keys:
  - **dir**: It defines the direction the gripper tip is pointing. "front", "back", "left", "right", "up", "down"
  - **x** (depth): Integer 0–100 (percentile; 0 = closest to body, 100 = most extended forward)
  - **y** (lateral offset): Integer 0–100 (percentile; 0 = far right, 100 = far left)
  - **z** (height): Integer 0–100 (percentile; 0 = lowest reachable, 100 = highest reachable)
  - **gripper_orientation**: "horizontal", "vertical"
- **speed**: Float
- **hold_time**: Float

### type: "movement"
Parameters:
- **repetition**: Integer
- **joint**: "shoulder", "elbow", "wrist", or a combination
- **directions**: A list of movement phases:
  - **degrees**: Dictionary per axis, e.g. {"x": 20}, {"y": -15, "z": 10}
  - **speed**: Float
  - **hold_time**: Float

### type: "path"
Parameters:
- **shape**: "line" or "arc"
- **joint**: "shoulder", "elbow", "wrist", or a combination
- **speed**: Float

Additional parameters when shape is "line":
- **axis**: "x", "y", or "z"
- **distance**: Float (positive or negative)

Additional parameters when shape is "arc":
- **plane**: "xy", "xz", or "yz"
- **radius**: Float
- **sweep**: Float
- **direction**: "cw" or "ccw"

[Semantic Readability Rules]

## Pose
1. dir
Choose that best matches the intended meaning.
   - `"front"`: Gripper tip points forward, away from the robot (e.g., offering a handshake)
   - `"back"`: Gripper tip points toward the robot's own body (e.g., indicating "me")
   - `"up"`: Gripper tip points upward (e.g., a raised-hand greeting pose, hi-five)
   - `"down"`: Gripper tip points downward (e.g., resting at attention)
   - `"left"` / `"right"`: Gripper tip points laterally (e.g., rubbing one's eyes or tapping the temple)
When the cue interacts with a body part or an implied object, choose the direction that makes the iconic meaning easiest to read.
For example, `tap stomach` and `akimbo` usually read better with a lateral (`left` or `right`) direction.

2. gripper_orientation
   - `"vertical"`: The gripper opening plane is perpendicular to the ground (e.g., a handshake or shush gesture)
   - `"horizontal"`: The gripper opening plane is parallel to the ground (e.g., waving hello, offering, or presenting)
If the cue implies interaction with an object or another person, choose gripper orientation deliberately.
For example, cup-like drinking motions usually read better with a vertical orientation, while waving hello and high-fives usually read better with a horizontal orientation.

3. Creating Non-Quantized Poses
Some iconic motions need an in-between angle rather than a fully quantized database pose.
For example, a salute that should lean at roughly 45 degrees may be better expressed as:
- a quantized pose with `hold_time: 0.0`
- followed immediately by a movement step with speed in the `0.5-4.0` range
- and a visible `hold_time` after that movement so the deformed pose can actually be read
This lets the movement-driven deformation create the readable pose instead of jumping only between quantized database poses.
Use this pattern when the readable target pose is clearly in-between quantized database poses, such as a salute angle, a bowed torso line, or a hand-over-heart placement.

If you want the initial quantized pose itself to remain visible before the movement begins, use:
- a quantized pose with `hold_time > 0.0`
- followed by the movement step


## Movement
1. Parameters
Tune the parameters so the motion is clearly visible and easy to distinguish.
Use speeds between `0.5` and `4.0`.
- `0.5–1.0`: slow / deliberate / weighty
- `1.0–2.0`: normal readable main action
- `2.0–4.0`: sharp accent only
Avoid speeds above `4.0`, because the motion may render in too few frames to read clearly.
   e.g., beckon: repetition 3-5, speed 1.2, hold_time 0.2
   e.g., salute: repetition 1, speed 1.5, hold_time 1.5
   e.g., shrug: repetition 1, speed 0.5, hold_time 0.7

2. Movement degrees (Axis)
Choose movement axes that align with the cue's meaning.
Also consider the correlation between pose gripper orientation and the movement axis.
Interpret `x`, `y`, and `z` as the viewer-visible spatial direction of the motion, not an internal robotics rotation label such as pitch, yaw, or roll.
- nod / up-and-down affirmation -> z
- shake head / side-to-side negation -> y
- wave hello / side-to-side greeting -> y
- fist-bump / forward extension -> x
- beckoning with horizontal gripper -> z
- beckoning with vertical gripper -> x
A single phase may also move along multiple axes at the same time (e.g., `{"y": -15, "z": 10}`).
Use multi-axis movement when the human motion inherently couples axes.
For example:
- bow / respectful torso lean -> use `x+z`, not just `x`
- deep apology bow -> use `x+z` with a longer hold at the lowest point
- recoil / shock -> use a coupled `x+z` motion when the body appears to pull back and rise at once
Do not split a naturally coupled motion into separate single-axis phases unless there is a clear semantic reason.


## Path
Use paths only when the trajectory itself is part of the iconic read.
For example, a semicircle in the `xy` plane can help create a hug-like motion.
Do not overuse meaningless line or arc paths.


## Body Spatial Reference
Imagine what body part or body configuration the motion is trying to evoke.
Place the pose where that read makes sense.
For example, a hug should wrap around a shoulder-height region, and a bow should not happen at an unrealistically high position.
Use this table to map human body parts to approximate gripper coordinates.

| Body Region              | z (height) | x (depth) | y (lateral) |
|--------------------------|------------|-----------|-------------|
| Above head               | 85–100     | 40–60     | 40–60       |
| Eye level                | 65–75      | 40-60     | 35–65       |
| Chest / heart            | 45–55      | 40-60     | 40–60       |
| Stomach / waist          | 35–45      | 40-60     | 40–60       |
| Arm resting at side      | 15–25      | 30-60     | 45–55       |
| Arm extended forward     | 40–60      | 70–90     | 45–55       |
| Arm raised high          | 80–95      | 30–70     | 40–60       |
